# Развертывание

## Текущий прототип

Адрес: https://elma-wiki-peter-preview.netbka.chatgpt.site/

Доступ в Sites остается только у владельца. Перенос исходников в публичный GitHub не меняет доступ к этому адресу и не подключает автоматический деплой.

## Обычный статический хостинг

1. Установить Node.js 22 и зависимости командой `npm ci`.
2. Выполнить `npm run build` и `npm run test:sites`.
3. Загрузить содержимое `dist/client/` в корень сайта на выбранном хостинге.
4. Подключить домен и HTTPS.
5. Проверить переходы, русский и английский языки, сохранение демо и загрузку с телефона.

Маршруты используют hash, поэтому для шести страниц не требуется серверный роутинг. Отдельная база для нынешнего демо не нужна: оно хранит прогресс в браузере посетителя. Для самостоятельной статической публикации Worker из `dist/server/` не нужен.

Проверку доступности из российских домашних и мобильных сетей выполнить перед запуском. Выбор провайдера, тариф и настройка домена остаются отдельной задачей. Здесь не приводятся обещания доступности или непроверенные цены.

## Обновление существующего Sites

1. Взять нужный проверенный commit из этого репозитория.
2. Открыть существующий проект Sites через его штатный процесс работы с исходниками.
3. Перенести изменения, сохранив текущий `.openai/hosting.json` и идентификатор проекта.
4. Собрать, проверить, синхронизировать снимок исходников и опубликовать его штатными средствами Sites.
5. Проверить результат публикации. Смена аудитории - отдельное действие владельца.

Не создавать второй сайт при обычном обновлении. Не сохранять токены Git, доступ к почте или другие секреты в исходниках.

## Форма связи

Сервис в `server/` принимает `POST /api/contact`: проверяет поля, сохраняет обращение на диск и только затем отправляет письмо. Если почта недоступна, обращение остается на диске, а повторная отправка идет каждые 5 минут и при запуске сервиса. Ответ посетителю можно отправить обычным «Ответить» в Gmail: адрес посетителя стоит в `Reply-To`.

Без сервиса сайт работает как раньше. Форма включается только при сборке с `VITE_CONTACT_ENDPOINT`, поэтому Sites продолжает показывать предпросмотр с пометкой «не отправлено».

Запуск:

1. Создать в аккаунте Google пароль приложения (нужна двухэтапная аутентификация).
2. Задать на сервере переменные окружения. В Git их не добавлять.

   | Переменная | Значение |
   | --- | --- |
   | `CONTACT_DATA_DIR` | Постоянный каталог вне репозитория и вне публикуемых файлов |
   | `CONTACT_TO` | Адрес, куда приходят обращения |
   | `SMTP_HOST`, `SMTP_PORT` | `smtp.gmail.com`, `465` |
   | `SMTP_USER`, `SMTP_PASS` | Адрес Gmail и пароль приложения |
   | `CONTACT_FROM` | Необязательно, по умолчанию `SMTP_USER` |
   | `HOST`, `PORT` | Необязательно, по умолчанию `127.0.0.1:8787` |
   | `CONTACT_TRUST_PROXY` | `1`, если сервис стоит за своим обратным прокси |

3. Запустить `npm run server` под менеджером процессов.
4. Настроить прокси так, чтобы `/api/contact` шел на сервис с того же домена, что и сайт. CORS сервис не поддерживает.
5. Собрать сайт с `VITE_CONTACT_ENDPOINT=/api/contact` и опубликовать `dist/client/`.
6. Отправить тестовое обращение и проверить письмо и ответ на него.

Ограничения: лимит 5 обращений в час с одного адреса хранится в памяти процесса, поэтому рассчитан на один экземпляр и сбрасывается при перезапуске. Сервису нужна постоянная файловая система и постоянно работающий процесс. Письмо может прийти дважды, если сбой случился сразу после отправки. Автоматического удаления старых обращений пока нет.

## Что еще требуется

- Для реальной формы: выбранный хостинг, почтовые настройки, согласованный текст обработки данных, срок хранения и удаление, проверка реальным письмом (см. раздел ниже).
- Для продолжения демо на другом устройстве: отдельная авторизация и хранение изолированных данных посетителей, срок хранения, сброс и удаление.
- Подключение реальных ELMA и AIWorks не входит в этот учебный сайт.
