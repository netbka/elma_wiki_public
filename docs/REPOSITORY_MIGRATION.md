# Перенос публичного сайта

Дата: 31 октября 2026.

Владелец попросил перенести сайт и связанную работу из `netbka/elma_wiki` в `netbka/elma_wiki_public`.

## Фактический источник

Проверка показала, что созданный в этой работе сайт находился в отдельном проекте Sites, а не в репозитории внутренней Wiki.

- Сайт: https://elma-wiki-peter-preview.netbka.chatgpt.site/
- Название: ELMA Wiki - публичный сайт и демо.
- Опубликованная версия Sites: 1.
- Commit исходников опубликованной версии: `b248c6d456ca495f23bb747c1a48c3a03056cf86`.

Локальная копия исходников имела этот же commit и чистое состояние Git. Из нее перенесены `src/`, Worker, настройки сборки, lockfile, существующие проверки, описание дизайна и пять изображений QA. Исходники интерфейса сохранены без изменений. Документация дополнена адресом основного репозитория и порядком публикации.

Зависимости, результаты сборки, временные файлы и история внутренней Wiki не импортировались. Существующие MIT LICENSE и .gitignore целевого репозитория сохранены.

## PR и issues

Проверены текущие файлы и ветки `elma_wiki`, открытые задачи, последние PR, а также открытые и закрытые результаты поиска по `elma-wiki-peter-preview`, `elma_wiki_public`, `публичный сайт`, `public site`, `prototype` и `demo`.

Связанных с этим прототипом PR или issues в `elma_wiki` не найдено. Поэтому переносить или закрывать существующие записи не потребовалось. Старые работы над публичным учебным порталом и актуальные работы по оформлению внутреннего приложения относятся к другим направлениям и остаются в исходном репозитории.

PR импорта и оставшиеся задачи публичного запуска создаются непосредственно в `elma_wiki_public`. Эти задачи фиксируют уже обсужденную работу; они не выдаются за перенесенные GitHub issues.

Зафиксированы: [форма связи #1](https://github.com/netbka/elma_wiki_public/issues/1), [публичный запуск #2](https://github.com/netbka/elma_wiki_public/issues/2), [последующее серверное сохранение демо #3](https://github.com/netbka/elma_wiki_public/issues/3).

## Дальнейшая работа

Все изменения публичного сайта, демо, формы связи и внешнего размещения ведутся здесь. Репозиторий внутренней Wiki остается отдельным проектом. Текущая публикация в Sites сохраняет адрес и аудиторию. GitHub и Sites не синхронизируются автоматически; порядок обновления описан в [DEPLOYMENT.md](DEPLOYMENT.md).
